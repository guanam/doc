# 定位任务书 —— ex 自捕获下单图占 10G、多 bs 精度异常

> **这是一个现场问题的定位任务书,不是 sglang 适配任务。** 把一个推理模型改写到 npugraph_ex 上、
> 由 ex 自己做 compile + capture 之后,踩到两件事:编译一个图就吃掉约 10G device 内存导致多 bs OOM;
> 以及调整 `clone_input` / `use_graph_pool` 之后多 bs 出现精度问题。
>
> **读者是远程环境里的 agent。** 这份文档自带全部上下文,不要去别处找背景。
>
> **本轮目标只有两个**:
> 1. 定位"多 bs 下精度不对"是哪一条机制(A / B / C 三选一或多选);
> 2. 拿到"一个图到底为什么占 10G"的分解数字。
>
> **本轮不改 npugraph_ex 的代码**,只改 `torch.compile` 的 options 并采数据。

---

## 一、现场(事实,不是推测)

场景:基于 SGLang 的服务框架 + 一个 MoE 模型(带多头 Eagle / MTP 投机解码),
已改写到 npugraph_ex 上,**由 ex 自己做 compile + capture**(未设 `force_eager`,
所以 `AclGraph.capture` / `process_input` 都会走到)。

> 注意区分:这里 ex 持有 capture。社区 sglang 自己那条路是 `force_eager=True` + 由 `NPUGraphRunner`
> 持有 capture,那种情况下 `clone_input` / `clone_output` 根本不生效(`acl_graph.py:920-923`
> 在 `compile()` 之前就 return 了)。**本问题的全部分析只适用于 ex 持有 capture 的情形。**

启动参数里和本任务相关的几项:

下表取一组有代表性的量级(具体数值因部署而异,**重要的是量级关系,不是某个确切值**):

| 项 | 量级 | 为什么相关 |
| --- | --- | --- |
| `--npu-compile-bs` | **3 个 bs 档**(如 `1,8,16`) | 档数直接乘进图的总数 |
| 投机解码 | `NEXTN`,`num-steps 3`,`num-draft-tokens 4`,多头 Eagle | **主模型 + 3 个 draft,且是链式**:主模型输出要喂给 draft。⇒ 图总数 ≈ 4 × 3 = **12** |
| `--mem-fraction-static` | **约 0.65** | 静态池(权重 + KV cache)吃掉约三分之二,图池只能用剩下的 |
| `max_model_len` × `max_running_requests` | **约 1M × 256** | ⇒ `req_to_token` ≈ `[257, 1M] int32` ≈ **1.0 GiB**,且它**与 bs 无关**,是非参数的普通张量输入 ⇒ 会被 `clone_input` 克隆 |
| EP 规模 | **较大(如 `--expert-parallel-size 128`)**,配 `--low-latency-max-num-tokens-per-gpu` | MoE dispatch/combine buffer 由后者定尺寸,**与 bs 无关** —— 这条决定第五节里 `use_graph_pool` 划不划算 |

三个现象:

1. **启动后 device 只剩约 13G,编译一个图就占约 10G**,主模型 + 3 draft × 多 bs ⇒ OOM。
   (13G 这个余量本身是 `mem-fraction-static` 的结果,不是异常)
2. 用 memory_viz 看到 **KV cache 的视图也被 clone 了**(当时 `clone_input` 是默认的 `True`)。
3. 把 options 改成 `clone_input=False` + `use_graph_pool`(共享一个句柄)之后,**多 bs 出现精度问题**。

## 二、已核实的代码事实(直接用,不要重新推导)

仓路径以 `npugraph_ex/npugraph_ex/` 为根。以下每条都已读码确认,部分在 910B3 上实测过。

### 2.1 图池的数量

```python
# _acl_concrete_graph/acl_graph.py:1006
aclgraph_cache_info.pool if aclgraph_cache_info.pool is not None else torch.npu.graph_pool_handle()
```

**不设 `use_graph_pool` 时,每个 FX 图各开一个新池。**

**910B3 实测**:`dynamic=False` 下 **每个 (模型, bs) 组合是一个独立 FX 图**。两个模型 × 两档 bs
拿到 4 个不同的池 `(0,2) (0,4) (0,6) (0,8)`。所以 4 模型 × 3 bs ⇒ **12 个 FX 图、12 个池**。

推论:`reuse_graph_pool_in_same_fx`(默认 True)**在这个场景几乎不起作用** —— 它要
`len(self._graphs_meta) > 1`(`acl_graph.py:1248`)才生效,而每个 FX 图只有一个 graph_key。

### 2.2 clone_input 克隆的是什么、在哪分配

```python
# acl_graph.py:1343  <- 注意这是 capture 上下文的入口
with torch_npu.npu.graph(self.graph[graph_key], pool=self.pool, stream=self.stream, ...):
    for input_name, input_idx in self._user_inputs_mapping.items():
        if input_name in self._mutated_user_inputs:        # :1346 跳过
            continue
        if input_idx in self._userinput_ref_with_output.keys():   # :1349 跳过
            continue
        ...
        if self.config.get('clone_input', True) and args_list[input_idx].is_npu:
            args_list[input_idx] = torch.empty_like(...)   # :1360 ← 从图池分配
```

- `empty_like` 在 capture 上下文**内部** ⇒ **克隆体从图池分配,地址被烤进图,图活着它就占着**。
- **权重/参数不会被克隆**:带 `_dynamo_static_input_type` / `_torchair_is_parameter` / 是 `nn.Parameter`
  的输入进 `parameter_user_inputs`,**根本不进 `user_inputs_mapping`**(`fx2acl_converter.py:429-437`)。
- 所以被克隆的只有:**非参数、非 mutated、非 output-alias、在 NPU 上**的普通张量输入。
  `req_to_token`(1.004 GiB)正好符合。

### 2.3 clone_input 的 True / False 在 replay 期语义完全不同

```python
# acl_graph.py:1484-1507  process_input
if self.config.get('clone_input', True):
    reconstructed_inputs = self._graphs_meta[graph_key].userinputs_metatensor
    for input_idx, capture_input in reconstructed_inputs.items():
        dst_tensors.append(capture_input); src_tensors.append(args[input_idx])   # 无条件全量拷
else:
    reconstructed_inputs = self._graphs_meta[graph_key].retained_userinputs
    for input_idx in graph_meta.userinputs_meta.keys():
        if graph_meta.userinputs_meta[input_idx].data_ptr != args[input_idx].data_ptr():
            ...                                                                  # 只在地址变了才拷
```

- **True**:每次 replay 把**所有**入参刷进 capture buffer。图读写的都是 **克隆体**,
  **没有任何拷回** ⇒ 图往被克隆的张量里写,写进克隆体,**真张量收不到**。
- **False**:capture 烤**真地址**,只在 `data_ptr` 变了才拷。写入落在真张量上。
- 还有:`retained_userinputs` 只在 True 时被 clear(`:1289-1291`);**False 时长期持有真实入参引用**。

### 2.4 "input mutation" 的识别有四道关卡,经过 view 写入时可能全漏

| 关卡 | 位置 | 漏法 |
| --- | --- | --- |
| `_find_mutated_user_inputs` | `_utils/graph_utils.py:139-157` | 只认 `node.args[0]` **本身就是 placeholder**;先 `view`/`select`/`as_strided` 再写就匹配不上 |
| `inplaceable_npu_ops` | `_acl_concrete_graph/graph_pass.py:164-173` | **白名单只有 3 个**:`npu_kv_rmsnorm_rope_cache_v2`(arg 5/6)、`npu_mla_prolog_v3`(arg 9/10)、`npu_add_rms_norm_v2`(arg 0/1) |
| `_mutated_input_reinplace` | `graph_pass.py:219-228` | 只找 epilogue `aten.copy_.default` 且 `args[0].op in ("placeholder","get_attr")` |
| `userinput_ref_with_output` | `fx2acl_converter.py:496` | `_is_alias_of` 只保护**被当输出返回**的入参;只写不返回不保护 |

四道都没拦住 ⇒ 这个张量进克隆循环。**现象 2(KV cache 视图被克隆)就是这么来的。**

### 2.5 重捕获只认已识别的 mutation

```python
# acl_graph.py:1808-1812
for idx, mutated_ptr in self._graphs_meta[graph_key].captured_mutated_inputs.items():
    if mutated_ptr != args[idx].data_ptr():
        return True      # 地址变了才重捕获
```

`captured_mutated_inputs` 来自 `_mutated_user_inputs`(`:1223-1226`)。**没被识别的那些,地址变了也不会重捕获。**

### 2.6 use_graph_pool 的代价与它的安全前提

```python
# fx2acl_converter.py:219-232
if self.config.use_graph_pool is not None:
    # ... Enabling reuse would lead to stale storage persisting across different FX graphs ...
    # outputs that remain alive after a graph replay can be passed to a user via an aclgraph
    # captured from another FX context, which will cause unpredictable errors.
    # Reusing inputs is safe because they are no longer alive by the time a subsequent
    # aclgraph executes.
    self.config.reuse_graph_pool_in_same_fx = False     # 强制关掉
```

注意最后那句安全前提:**"后一个 aclgraph 执行时,前一个的东西已经不活了"**。
投机解码是 **主模型输出 → draft 输入 → 再串 3 步**,这个前提**不成立**。

传法(已验证可行):`options={"use_graph_pool": handle}`。
`compiler_config.py:65` 把它放进 `_fixed_attrs`,`_process_kwargs_options`(`:211`)的 `setattr` 因此被
`configs/_option_base.py:236` 放行;`npu_fx_compiler.py:681` 读 `self.config.use_graph_pool` 交给
`AclConcreteGraph(pool=...)`。**4 个模型必须传同一个句柄**,各自 `graph_pool_handle()` 等于没改。

### 2.7 clone_output:上游自己写明它会导致精度问题

```python
# acl_graph.py:1659-1672
outputs = self._clone_outputs_if_enabled(outputs)
if not self.config["clone_output"]:
    self.set_reconstructed_outputs_deleter(graph_key, outputs)
    warnings.warn(
        "Because acl graph fixes memory addresses, ... The retained memory of acl graph output "
        "tensors will be overwritten by subsequent executions, which may cause precision issues. "
        "... To resolve this, you can either: 1. Remove the memory retention of all the output "
        "tensors in your script; 2. Enable debug option by setting clone_output=True.")
```

默认 `clone_output=False`。`_clone_outputs_if_enabled`(`:1576-1587`)会跳过 storage 落在
`userinput_ref_with_output_storages_ptr` 里的输出。

### 2.8 内存快照的工具链(有个坑)

- **装的 `torch_npu` 的 `memory_snapshot()` 不接受 `mempool_id` 参数**(源码仓 `pta` 里有,装的包里没有)。
  所以要用 `torch_npu.npu.memory._snapshot()` / `_dump_snapshot(path)` 取**全量**,再按
  **`segment["segment_pool_id"]`** 自己过滤 —— 这个字段是有的,实测可用。
- pickle 结构:`{'segments': [...], 'device_traces': [...]}`;
  segment 有 `total_size / active_size / segment_pool_id / blocks / frames`,block 有 `size / state / frames`。
- 看图:`https://pytorch.org/memory_viz`(**纯前端,不上传**)。视图选
  **`Allocated Memory (incl. Private Pools)`**,私有池是**灰色条**并标 `Private Pool ((0,2)): capacity ...`;
  有 `Search stack frame...` 过滤框,打 `acl_graph` 可单独筛出克隆。
- 命令行:`python3 -m torch.cuda._memory_viz {stats,segments,memory,trace,compare,trace_plot} *.pickle`
  (实测能吃 NPU 产的 pickle)。**`compare before.pickle after.pickle` 最有用。**
- ⚠️ **栈帧经常取不到**(实测图池里的大块常是 `<no frames>`),所以**不要只依赖栈归因**,
  要用探针里的"应克隆字节数"做交叉校验。

## 三、三条待验机制

| | 机制 | 内容 | 它预测什么 |
| --- | --- | --- | --- |
| **A** | `clone_input=False` + 未被识别的 mutation | 图往捕获期**旧地址**写;该入参不在 `captured_mutated_inputs` ⇒ 地址变了也不重捕获;`process_input` 只把新→旧拷过去,**写出去的到不了新张量** | 存在"地址真的换过、且不在 mutated"的入参。不同 bs 走不同 buffer 路径 ⇒ 随 bs 变 |
| **B** | `use_graph_pool` 跨 FX 图共享 | 2.6 的安全前提在链式拓扑下不成立;12 图共一池,**哪块压哪块取决于捕获顺序和各 bs 尺寸** | 单改池就复现;单改 `clone_input` 不复现 |
| **C** | 输出被后续 replay 覆盖 | 2.7 的上游警告直接点名 "may cause precision issues"。主模型输出在 draft 执行期间仍被持有 | **`clone_output=True` 一开精度就恢复** |

**C 最便宜且最可能,先验 C。**

## 七、若确认机制 A,根因修法候选(本轮不做,交上游)

**根因是"某入参的 mutation 没被识别",正确的修法是让它被识别,而不是在 `clone_input` 的
True / False 之间选一个少错的** —— True 丢写入、False 丢地址更新,两边都错。

候选:

1. **`_find_mutated_user_inputs` 加 view 穿透**(`graph_utils.py:152`):
   `node.args[0]` 不是 placeholder 时,沿 view 链向上回溯到基张量再比对。
   `_find_cond_mutated_bases` 已有类似的回溯思路可参考。
2. **把写 KV 的那个算子注册进 `inplaceable_npu_ops`**(`graph_pass.py:164-173` 三行模板),
   前提是它有 functional / inplace 成对的变体。
3. 兜底:把被写的张量同时作为图输出返回,让 `userinput_ref_with_output`(`fx2acl_converter.py:496`)
   接住它 —— 这需要改模型侧,侵入性最低但最不优雅。

先用 T3 的 `MOVED + 不在 mutated` 列表锁定具体是哪个入参,再对号入座。

## 八、本轮不做的事

- **不改 npugraph_ex 的代码。** 本轮只改 options 和采数据。
- **不同时改两个开关。** T4 / T5 必须各自单独改,否则结论不可归因(上一轮就是因为一起改了才卡住)。
- **不把 `clone_input` 当最终修法。** 它只是在两种错法之间选,见第七节。
- **不依赖栈帧归因。** 实测常取不到,用探针的"应克隆字节数"交叉校验。
